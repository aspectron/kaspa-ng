Why a direct version change did not build
----------------------------------------
NG master uses workflow-rs 0.19 and wasm-bindgen 0.2.126/js-sys 0.3.103.
Official RK v2.1.0 uses workflow-rs 0.18 and pins wasm-bindgen 0.2.100 /
js-sys 0.3.77. Replacing the sigma reference with the v2.1.0 tag fails
dependency resolution. The existing sigma SDK compatibility changes were
therefore applied on top of the official v2.1.0 release.

The port preserves the existing workflow, WASM ABI and TLS adaptations.
The redundant global risc0 export-syscalls dependency from sigma was
omitted: v2.1.0 already contains the Windows-specific dependency.
The SDK Cargo.lock was updated from the release lockfile.
These are adaptations of existing Aspectron work, not a new consensus
implementation. The integration still requires independent review.

NG changes
----------
All 17 RK workspace dependencies use the same immutable integration commit.
Cargo.lock resolves the RK packages to version 2.1.0 from that commit.
Network::tps uses Params.block_mass_limits.reference(), matching the
v2.1.0 API after removal of the pre/post-activation accessor.
NG's application version remains 2.0.1; its embedded node is 2.1.0.

Validation performed on Windows x86_64, Rust 1.95.0
---------------------------------------------------
With the local SDK source matching the integration commit:
- cargo check --locked --workspace --tests --benches: passed.
- cargo test --locked --workspace --lib: passed (3 tests).
- cargo build --locked --bin kaspa-ng: passed (development profile).
- kaspa-ng.exe --help identifies rusty-kaspa 2.1.0.
- kaspa-ng.exe --daemon --version prints "kaspad 2.1.0".
  The daemon version path returns exit code 1 because NG treats clap's
  display-version result as a parse error; this behavior was not changed.

The three NG tests cover the markup parser, generic transaction-mass
calculation and fee averaging. They are not a full wallet or consensus test.

After replacing local paths with the published immutable SDK Git reference,
cargo check --workspace --tests --benches also passed. The local SDK tree
was committed without further source changes before publication.

Additional SDK validation (Windows x86_64, Rust 1.95.0)
-----------------------------------------------------
- cargo fmt --all -- --check: passed.
- cargo clippy --locked --workspace --tests --benches: passed.
- cargo nextest run --locked --workspace --lib --test-threads 4:
  1022 passed, 14 skipped. Development profile (not a release-profile run).
- All 13 wasm32 compile/clippy feature and test-module checks corresponding
  to the SDK check script: passed. These compile tests; they do not execute
  the WASM tests in a browser or Node.js.

the approved immutable commit and regenerate Cargo.lock. Complete the
remaining platform/runtime validation before publishing an official release.
